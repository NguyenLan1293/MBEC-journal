# Segmentation — Code Usage Guide

## 1. Configuration

The main configuration constants are defined in **Block #1**:
* `PREICTAL_SEC`: Duration of the preictal period, in seconds.
* `INTERICTAL_DIST_SEC`: Minimum temporal distance required between an interictal segment and a seizure, in seconds.
* `MIN_SEIZURE_GAP_SEC`: Minimum gap between two separate seizures, in seconds.
* `CONTINUOUS_TOLERANCE_SEC`: Maximum gap between two recordings for them to be considered continuous, in seconds.
* `EPOCH_LEN_SEC`: Length of each EEG epoch, in seconds.
* `LOCAL_DATA`: Path to the CHB-MIT dataset in the Kaggle session input directory.
* `SAVE_ROOT`: Output directory where the segmented data will be saved.
Make sure these parameters are configured correctly before running the code.

## 2. Dataset

This code was developed and tested using the following **CHB-MIT dataset**:
https://www.kaggle.com/datasets/abhishekinnvonix/seizure-epilepcy-chb-mit-eeg-dataset-pediatric
We recommend using the same dataset version. Using a different dataset or directory structure may cause compatibility issues, particularly with:
* file paths;
* file naming conventions; and
* text-based chb searching implemented in the code.
If another version or source of the CHB-MIT dataset is used, the corresponding paths and chb-searching logic may need to be modified.

## 3. Summary Files

The `summary_path` / `summary_dir` variables specify the location of the CHB-MIT summary files, such as:
```text
chb01-summary.txt
```
These summary files contain the seizure onset/offset information used during the segmentation process.
Make sure that the summary files are available at the specified location and that the paths are consistent with the dataset structure.

## 4. Computational Resources and Recommended Execution

The segmentation process can be **time-consuming and disk-intensive**, particularly when processing the complete CHB-MIT dataset. Intermediate and output files may require a substantial amount of local disk space in the Kaggle session. If the code cannot be executed efficiently on a high-performance computer (HPC), we recommend dividing the workflow into two phases:
* **Phase 1 and Phase 2**
* **Phase 3**
Run each phase in a **separate Kaggle notebook version/session**. This approach can help reduce the disk usage and computational burden within a single Kaggle session. Before moving to the next phase, make sure that the outputs generated by the previous phase have been successfully saved and are available as inputs for the subsequent stage.
